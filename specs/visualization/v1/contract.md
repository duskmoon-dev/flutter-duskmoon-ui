# Duskmoon Visualization Contract 1.0.0

Version 1.0.0 covers the portable input and observable behavior of the six Duskmoon visualization components. The Web repository owns the editable contract. The Flutter copy is a snapshot. The capability matrix records scope and implementation status separately. Use the fixtures and paired expected results to verify behavior independently of rendering libraries.

## Inputs and validation

Use the Draft 2020-12 schemas in `schema/` for JSON structure. Apply the semantic rules below after shape checks. Accessors and platform time objects must resolve to the same portable model. Numbers are finite binary64, and IDs are nonempty case-sensitive Unicode strings. Reject unpaired surrogates. Compare IDs exactly without Unicode normalization. Series IDs are unique within a chart, datum IDs within a series, and cell, row, column, node, edge and feature IDs within their respective collections. A datum is addressed by the pair of series and datum IDs. Labels may repeat. Metadata is an opaque JSON object.

Return issues with `code`, `path` (RFC 6901 JSON Pointer) and `severity` (`error` or `warning`). An error prevents rendering data. Report the offending occurrence for duplicate IDs or coordinates, starting with the second occurrence. Warnings preserve the input and allow other data to render. Collect errors in input traversal order within each validation pass. Fixtures match issues by code, path and severity.

| Code | Trigger |
| --- | --- |
| `invalidShape` | Schema shape or unsupported field, axis type or option |
| `invalidId` | Invalid Unicode in an ID |
| `duplicateId` | An ID repeats within its collection |
| `unknownReference` | Unknown node endpoint, heatmap row/column, or hidden series ID |
| `duplicatePosition` | Two cells occupy one row/column pair, or two bars occupy one category in a series |
| `invalidNumber` | Non-finite native numeric input or arithmetic that cannot produce a finite domain |
| `invalidTime` | Time outside the accepted range or invalid date/time text |
| `invalidDomain` | Continuous explicit domain is unordered or degenerate |
| `invalidFormat` | Formatter incompatible with the axis or invalid locale/time zone |
| `unsupportedGeometry` | Unsupported geometry, out-of-range position, unclosed ring, or an edge crossing the antimeridian |
| `missingCoordinate` | Scatter datum with null x or y. Emit one warning at the datum path |

For the specialized errors above, use the specialized code even when the schema also detects the failure. Continuous axis x values must match their configured type. Numeric y and bar values may be negative. `null` denotes missing data, and zero is data. For line, null x always breaks a segment and null y breaks it by default. With `connectMissing`, skip null y only. Scatter skips a datum with either coordinate missing. Bar skips null x or y and retains zero bars in keyboard/data access. Heatmap assigns the missing color to explicit null cells and absent row/column pairs. Only explicit cells have an ID and can be selected.

## Axes, order and formatting

Time normalizes to UTC Unix epoch milliseconds, limited to ±8,640,000,000,000,000. Text uses four-digit Gregorian dates, uppercase T and Z or an explicit ±HH:MM offset, seconds 00–59 and optional 1–3 fractional digits. Validate the calendar and offset (hours 00–23, minutes 00–59) before conversion. Never normalize overflowing dates. Display timezone has no effect on normalization. Use decimal, UTC ISO with three fractional digits, IANA-zone date/time, or category label formatting as appropriate. The strict date-time vector uses `en-US` and the fields YYYY-MM-DD HH:mm:ss ±HH:MM, with ASCII digits and a 24-hour clock. Decimal uses the locale's decimal separator, defaults to `en-US` and up to three fractional digits, never groups by default, rounds ties away from zero, and displays negative zero as zero. Append a unit with one space when shown inline. Category labels default to their IDs.

A category domain contains IDs. Use the explicit order when supplied, otherwise use first appearance across input series and data order, including categories with missing y. Optional `categories` supplies display labels, without adding domain entries. `domainAfterHide: visible` filters the domain input before inference. Explicit domains exclude out-of-domain categories from rendering. Keep all original data available for summary/export. Place category points at their band centers. Infer continuous domains from all drawable paired input even when an explicit domain on the other axis clips some points. Line preserves input order and repeated x by default. `sortX: true` sorts stably by numeric/time x or category domain index within each run bounded by null x. Heatmap uses the given row and column order.

Use an explicit increasing finite continuous domain as supplied after time normalization. Otherwise take min/max from drawable paired values (bar uses drawable values only, including zero). Only apply `includeZero` after finding at least one valid value. Numeric axes default false, except bar y requires a zero baseline in automatic mode. For bar explicit domains, clamp zero to the domain for the visible baseline. Heatmap color domains follow the same numeric inference and never include zero by default. A chart with no drawable data has an empty state even when a domain is supplied. An inferred domain with no values is null.

If an inferred numeric domain is constant, extend by ±1 at zero or ±5% of the absolute value otherwise. If an inferred time domain is constant, extend by ±1,000 ms. Reject non-finite or non-increasing results. For `nice: true` on inferred domains, take one fifth of the expanded span and choose the smallest step at least that large from the sequence 1, 2, 5 × 10^k. Round the lower bound down and upper bound up to step multiples. Use one millisecond as the minimum time step. Leave explicit domains unchanged. All valid series are visible initially and count for inference after hiding by default. With `domainAfterHide: visible`, infer only from series still visible. Geometry is clipped to the plot. Explicit `tickValues` have the supplied order, with out-of-domain values excluded.

## Color and layout

Colors in portable payloads are opaque sRGB `#RRGGBB`. Serialize expected colors in uppercase. A datum color overrides series color. An explicit series color overrides slot mapping. Use an explicit nonnegative `paletteSlot` modulo palette length, or compute unsigned 32-bit FNV-1a over the UTF-8 series ID. Start at 2166136261 and for each byte XOR it into the hash, multiply by 16777619, and retain the low 32 bits. Use unsigned hash modulo palette length. Palette overrides precede the Duskmoon theme, and categorical colors are separate from status colors. Collisions are allowed. Reordering, filtering, hiding and restoring do not affect mapping with the same palette.

Map background/plot to surface/surface-container-low, grid to outline-variant, axis to outline, text/muted text to on-surface/on-surface-variant, tooltip to inverse-surface/inverse-on-surface, crosshair to on-surface-variant, selection to primary and missing to surface-container-highest. The default series palette in order is primary, secondary, tertiary, primary-container, secondary-container and tertiary-container from the active Duskmoon theme. The default heatmap endpoints are surface-container-highest and primary. Contract fixtures supply explicit sRGB colors for strict comparisons.

For a heatmap color, clamp the value to the domain and normalize to [0, 1]. When all valid values are equal and no explicit domain is supplied, sample at 0.5. Stops are evenly spaced inclusive of both endpoints. Interpolate encoded sRGB channels independently and round each channel to the nearest integer with ties upward. For missing cells use the resolved missing token.

Positions in geometry fixtures are normalized to a unit plot, origin at top left. A continuous increasing x maps from left to right, and increasing y maps from bottom to top. Category bands divide their dimension equally. Default grouped bars evenly subdivide a category band among visible series in input order, reserving a slot for an explicit missing item or absent bar in that series. The slot is the normalized bar extent for geometry comparisons. Vertical categories run left to right and horizontal categories top to bottom, with the numeric scale increasing rightward. Heatmap rows run top to bottom and columns left to right, with each axis divided evenly. Line defaults to linear, with markers hidden. Scatter defaults to circle and radius 4 logical pixels. An explicitly shown line marker uses the same radius by default. Heatmap labels are opt-in.

Use a 1 logical-pixel axis/grid and a 2 logical-pixel line stroke. Use plot insets of 16 logical pixels with measured space reserved for axes and wrapping legend. Use theme label and body typography and 8 logical pixels between legend items. Below 360 logical pixels of container width, wrap legend items, ellipsize overflowing labels, and expose the original text via accessible name or tooltip. Use the full measured plot once available and a placeholder until it has positive dimensions. Use named titles, descriptions, summaries, keyboard/Semantics controls and accessible underlying data. Indicate selection by more than color. Provide loading, empty and error states. Disable animation for snapshots and honor reduced-motion preferences at runtime.

## State and events

Use the event schema for the portable payload. Default selection is empty and single. Treat IDs as a set, serializing in selection order. A single select replaces selection, activation of the current item is a no-op, and multiple selection toggles membership. Clear/reset emits a selection event only if the set changes. Hiding a series suppresses hover for it and preserves its selections. Reordering preserves state. Data removal prunes references silently during input reconciliation. Tooltips expose the stable target, original values, formatted display and optional unit, and dismiss on exit or cancellation without emitting a tooltip payload. Use `{x,y}` for datum raw values, `{value}` for a cell, `{x,y}` for a node, `{source,target}` for an edge, and `{value}` for a map feature when its properties has a numeric value. For other map features use an empty raw object. Event targets are also available through keyboard or native accessibility and touch.

Selection, visibility and viewport can be controlled independently. User action emits the proposed change once per completed semantic action. The owner updates controlled state. Reconciliation and controlled prop writeback do not emit user events. Compare normalized state to suppress no-op proposals. Tooltip focus may stay local. A focus action on the same target and payload produces no duplicate event. Increment `revision` to signal changes when a platform wrapper reuses an input reference.

Line numeric/time zoom returns an increasing x domain and brush returns an increasing x range, in data units or normalized epoch milliseconds. A brush is independent of zoom. Scatter zoom returns increasing x and y domains. Network/map zoom uses the typed viewport below. On reset restore the initial or inferred state and emit the changed events in order: selection, visibility (series order), viewport, brush. Null brush range means cleared. Scene drags take precedence over tap, and active brush or node drag takes precedence over pan. Cancelled gestures emit no commit event. Use inverse viewport transforms for hit testing. Scope per chart is in the capability matrix.

## Network and map

Network uses input positions with x rightward and y downward, and edges drawn as straight segments by default. Nodes and edges have separate ID namespaces. Use the bounding box center and a uniform aspect-preserving fit as the initial viewport, expanding a zero span by ±1 on that axis. In layout coordinates viewport holds `center` and `zoom` as a positive multiplier of initial fit scale (default 1). Drag commits a new finite layout position via `nodeMove`; use the current transform inverse. Fixed layout is the common mode.

Map takes a GeoJSON FeatureCollection, with string ID, properties and a Point, Polygon or MultiPolygon geometry per feature. An optional numeric `properties.value` is the feature measure. Position order is longitude then latitude in degrees. The supported bounds are ±180° longitude and ±85° latitude. Reject consecutive ring vertices differing by more than 180° longitude. Rings are closed, outer ring first, holes thereafter; winding does not change fill. Fit includes points and all outer rings. Use spherical Mercator in radians: u = longitude, v = −asinh(tan(latitude)). Use the midpoint of projected bounds unless a center is supplied in lon/lat. With an explicit center, use twice the maximum projected distance from center in each dimension as the fit span. Expand a zero span to one projection unit centered on the point. Use the smaller ratio of available width/height (after symmetric padding of 16 logical pixels by default) to the corresponding fit span. Non-positive available dimensions delay layout. Viewport uses lon/lat center and positive zoom multiplying initial fit scale (default 1). Use the inverse projection when panning. A point on an outer boundary is a hit and a point on a hole boundary is excluded. At overlapping features use last drawn order, with Point markers drawn over region fills.

## Fixture conventions

Files in `fixtures/` and `expected/` pair by basename and test case ID. Inputs are charts unless a case supplies `mutations` or `actions`. A mutation replaces the JSON Pointer target before validation. The mutation values `{"nativeNumber":"NaN"}`, `{"nativeNumber":"+Infinity"}`, and `{"nativeNumber":"-Infinity"}` are adapter directives in fixtures only. Flatten expected numeric geometry and compare using the case's absolute tolerance. Legacy compatibility vectors are compiled against each platform's API independently.

Interaction actions are semantic test inputs. `focus` targets a chart item, `activate` selects or toggles one item, `writeSelection` simulates external writeback, `toggleSeries` inverts its visibility and `zoom` proposes the supplied viewport. `brush` supplies a data-space range. `dragNode` commits the node at the given normalized plot position. `clearSelection`, `cancel` and `reset` model the matching semantic actions. `controlled` lists owner-controlled state fields for a case. A tooltip datum uses the y/value formatter and unit. `geometry` point entries are [x, y], rect entries are [left, top, width, height], and scene `hitLocations` are tested in geographic coordinates. Fixture object keys identify items within that case.
